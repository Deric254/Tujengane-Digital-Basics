Naming Files & Entries

Use clear, consistent names for files and data entries.

  • Use dates in filenames (e.g., Sales_2023-01-01)
    Easy to find
  • Keep names descriptive
    Know what’s inside
  • Avoid special characters
    Prevents errors

Practice layer

Adopt a naming pattern and use it for every file:

Sales_2023-01-31.xlsx
Expenses_2023-01.xlsx
Customers_Mombasa_2023.xlsx

Rules: start with what it is, then the date in year-month-day form so files sort chronologically, use underscores instead of spaces, and avoid characters like / \ : * ? " < > |, which Windows does not allow. Same pattern for entries: always "Maize flour 2kg", never "unga" in one row and "flour" in another.

Level-up layer

Version names like "final", "final2", "REALLYfinal" signal a missing system; use a date or v01, v02 instead. Keep one master file and avoid copies emailed around. Put the date at the end for files you update, and at the start if you list many dated files. Short beats long: paths over about 250 characters can fail on Windows. Apply the same discipline to product names in your sheet, keeping a product list with fixed names. Next, handle blanks and guessing.

Check yourself: Why use 2023-01-31 instead of 31-01-2023 or Jan 31 in filenames?

Answer: Year-month-day order sorts in true date order alphabetically, so files line up chronologically automatically.
